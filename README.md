# ナビ最短経路アルゴリズム教材

日本全国の任意の地域で道路グラフを読み込み、ナビが道を探索する様子を可視化できる教材です。
初期ルートには、公共性が高く分かりやすい「鹿児島中央駅 → 天文館」を使用します。
探索済みの道がアルゴリズム別の色で広がり、最後に決定したルートが黄色で描かれます。

## Web版を使う

`index.html` から、次の操作をブラウザ上で試せます。

- BFS・ダイクストラ法・A*探索の切り替え
- 駅名・公共施設・観光地・住所を検索し、日本全国から2地点を選択
- 線路を道路と異なるデザインで表示し、駅・電停を駅名付きで表示
- コンビニ、小学校、中学校、高校、大学、スーパー、レストラン、弁当店、カフェ、薬局、病院、公園、図書館、駅を現在の地図周辺から近い順に検索
- 遠方のスタート地点を選ぶとその周辺地図へ移動し、ゴール用の施設カテゴリをスタート地点から近い順に表示
- 読み込んだ地域の地図をクリックして、地点を微調整
- 探索アニメーションの再生、一時停止、速度変更
- 探索途中の中止（地点と探索方法は保持して準備完了へ戻る）
- 探索完了後、地図・探索済み道路・決定ルートを含むアニメーションGIFをブラウザ内で生成して保存
- 探索済み地点数・計算時間・評価値・決定ルートの確認
- スマートフォン、タブレット、PCの画面幅に合わせたレスポンシブ表示

場所検索は日本国内に限定しています。道路データの大きさと教材画面の見やすさを保つため、2地点は直線距離6 km以内で選びます。

道路データをブラウザから読み込むため、`index.html` を直接ダブルクリックするのではなく、このフォルダで簡易Webサーバーを起動します。

```powershell
python -m http.server 8000
```

その後、ブラウザで <http://localhost:8000/> を開いてください。外部ライブラリやビルド作業は不要です。

### GitHub Pagesで公開する

Web版はすべて相対パスで読み込む静的サイトなので、そのままGitHub Pagesに置けます。

1. このフォルダをGitHubリポジトリのルートへ追加して、`main` ブランチへpushする
2. GitHubのリポジトリで **Settings → Pages** を開く
3. **Deploy from a branch** を選び、`main` と `/(root)` を指定して保存する

公開後も探索計算とアニメーションは閲覧者のブラウザ内で動きます。一般的な場所検索時だけNominatim、初めて表示する地域の道路・鉄道・駅・周辺検索用施設を取得する時だけOverpass APIへ接続します。施設カテゴリ検索は取得済みデータを使い、施設取得だけ失敗していた場合はその時点で小範囲に分けて再取得します。

### 全国公開時のAPI運用

GitHub Pagesだけでも全国検索は動作します。ただし、公開APIは無制限に使えるサービスではありません。

- 場所検索は利用者が検索ボタンを押した時だけ実行し、同じ検索結果をブラウザへ30日間保存します。入力中のオートコンプリートは行いません。
- Nominatim公開APIの上限に合わせ、同じブラウザからの検索は1秒に1回以下に制限しています。
- 道路データは選んだ2地点の周辺だけ取得し、同じ地域のデータをブラウザへ7日間保存します。
- 道路と施設を別々の軽量クエリで取得し、広域または失敗時は範囲を自動分割して再試行します。
- 施設APIだけが混雑した場合も道路探索は続行し、属性検索時に施設データだけ再取得します。
- APIのURLや距離上限は `app-config.js` に分離してあり、提供先を変更できます。

学校内・授業・小規模な一般公開ではこの構成から始められます。アクセス数が増える全国向けサービスにする場合は、GitHub Pagesの前段にキャッシュ付きAPIプロキシを用意するか、利用量の契約があるジオコーディング／道路データ提供サービスへ切り替えてください。GitHub Pagesにはサーバー処理がないため、サイト全体からNominatimへ送られる検索を「合計1リクエスト/秒」に制御できないためです。

- [Nominatim Usage Policy](https://operations.osmfoundation.org/policies/nominatim/)
- [Nominatim Search API](https://nominatim.org/release-docs/latest/api/Search/)
- [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API)

## 完成GIF

| ファイル | 方法 | このGIFで見るポイント |
|---|---|---|
| `01_bfs_hayato_to_kosen.gif` | BFS（幅優先探索） | 通った「区間数」が少ない候補から波紋状に探索 |
| `02_dijkstra_hayato_to_kosen.gif` | ダイクストラ法 | 出発点からの実距離が短い候補から探索 |
| `03_astar_hayato_to_kosen.gif` | A*探索 | ゴールまでの直線距離も予想し、探索を目的地方向へ絞る |

生成時の結果は次のとおりです。

| 方法 | 決定ルート | 道路区間 | 探索済み地点 | 探索計算（実測） |
|---|---:|---:|---:|---:|
| BFS | 2.09 km | 20 | 774 | 1.39 ms |
| ダイクストラ法 | 2.06 km | 23 | 985 | 5.56 ms |
| A*探索 | 2.06 km | 23 | 179 | 1.69 ms |

ここでの「道路区間」は、交差点・分岐・行き止まりの間を1区間としたものです。
BFSは区間数を最小にしますが、各区間の長さが違うため実距離が最短とは限りません。
ダイクストラ法とA*は道路の長さを使うため、同じ距離最短ルートになります。
計算時間は今回のPCで探索開始から経路復元までを1回実測した値です。道路データの読込・グラフ構築・画像描画・ファイル保存は含みません。実行するたび、またPCや負荷によって値は変わります。

各方式の探索済み道路は1色に統一しています。BFSは緑、ダイクストラ法は青、A*は紫、最後に確定したルートは共通の黄色です。

## すぐに再生成する

Python 3.10以上とPillowを用意します。

```powershell
python -m pip install -r requirements.txt
python route_gif.py
```

3本のGIF、最終ルート確定画面のPNG 3枚、計算結果 `route_metrics.json` が現在のフォルダに生成されます。
1方式だけなら、次のように指定します。

```powershell
python route_gif.py --algorithm astar
```

主なオプションは `python route_gif.py --help` で確認できます。

## 別の場所にも使う

### 1. 道路データを取得

対象地点を囲む範囲を、南・西・北・東の順に指定します。

```powershell
python fetch_osm_data.py `
  --bbox 35.0000 135.0000 35.0300 135.0400 `
  --output data/my_roads.json
```

### 2. 出発地と目的地を指定してGIF化

```powershell
python route_gif.py `
  --data data/my_roads.json `
  --start 35.0050 135.0060 `
  --goal 35.0250 135.0320 `
  --start-label 出発地 `
  --goal-label 目的地 `
  --prefix my_route
```

プログラムは指定座標を同じ連結道路網上の最寄りノードへ自動的に接続します。
道路データ取得時はOverpass APIへのインターネット接続が必要ですが、同梱JSONからのGIF再生成はオフラインでできます。

## プログラムの構成

- `index.html` — Web版の画面
- `styles.css` — GIF版の配色・レイアウトを引き継いだWeb版デザイン
- `app-config.js` — 検索・道路API、距離上限、初期データの設定
- `route-core.js` — 道路グラフ構築とBFS・ダイクストラ法・A*探索
- `app.js` — 全国検索、道路取得、地点選択、Canvas描画、探索アニメーション
- `route_gif.py` — グラフ構築、BFS・ダイクストラ法・A*、GIF描画を行う本体
- `fetch_osm_data.py` — 任意範囲の道路をOverpass APIから取得
- `data/hayato_walking_roads.json` — 同梱した隼人駅〜鹿児島高専周辺の道路データ
- `data/kagoshima_central_walking_roads.json` — Web版の初期表示用道路データ
- `route_metrics.json` — 今回の計算結果
- `*_found.png` — 各アルゴリズムがルートを発見した最終画面
- `発表用解説.md` — 中学生向けにそのまま使える説明の流れ

道路グラフでは「交差点・分岐」をノード、「その間の道路」をエッジにします。
OpenStreetMapの細かな形状点は、探索前に交差点間の1本の道路へまとめています。
歩行向け教材のため、高速道路・工事中道路・徒歩禁止・私有アクセスの道路は除外します。

## 注意点とデータ出典

この成果物はアルゴリズム学習用です。通行止め、横断歩道、歩道の状態、工事、交通規制などをリアルタイム判定する実用ナビではありません。実際の移動には公式の交通情報やナビを確認してください。
